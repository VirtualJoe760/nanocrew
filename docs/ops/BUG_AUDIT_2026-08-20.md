Notated during the 14-agent documentation audit: every doc verified against the code, and
these are the code defects that surfaced. Deduplicated (several were spotted independently
by multiple auditors — those list every spotter). Status moves to `fixed` in the commit that
fixes it; anything marked **JOE-DECISION** needs a product/ops call, not just code.

## Major

### 1b. Publish updates the HQ store but not the brand's own website (Joe field report, 2026-08-20)
- **Status:** diagnosed + copy fixed — pipeline was never broken
- **What:** Joe published a bulldog shirt to the Stephen Lawyer brand and it didn't show on
  stephenlawyer.clothing. Diagnosis: everything worked — the product row landed on the right store,
  `revalidateStorefront` fired three Vercel redeploys (00:09 ×2, 00:19), and the site serves the
  product now. What bit was **latency + dishonest copy**: a full Vercel rebuild takes ~2–5 min, but
  Eve said "It's live — in your catalogue and on your site" instantly, so checking during the
  rebuild window reads as a broken publish.
- **Fixed:** honest timing copy on both surfaces (eve-design.tsx spoken cue + done line;
  FinalizeSheet done screen gains "Your site refreshes itself in a couple of minutes").
- **Follow-up (open):** replace the full-redeploy revalidation with template-level on-demand ISR so
  the site updates in seconds, not minutes — a template-level feature, tracked for a later pass.
  Also `storefront-revalidate.ts` silently returns when `VERCEL_TOKEN` is unset — add a warn log.
